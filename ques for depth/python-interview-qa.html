Language Fundamentals
Q1 – Q10

Python is a high-level, dynamically typed, garbage-collected language. CPython (the reference implementation) is both compiled and interpreted: source → AST → bytecode (in __pycache__/*.pyc) → executed by the ceval evaluation loop, a stack-based virtual machine written in C.

  • CPython – reference, C-based, has the GIL.
  • PyPy – JIT-traced, often 4–10× faster on loops, weaker C-extension compat.
  • Jython / IronPython / GraalPy – JVM / .NET / GraalVM hosts (no GIL, niche).
  • MicroPython / CircuitPython – microcontrollers.
💡 One-liner: "Python compiles to bytecode for a VM — files just cache it so step 1 is skipped next run."

Type hints (PEP 484+) add optional static typing checked by mypy/pyright — the runtime ignores them (except typing.get_type_hints introspection and pydantic-style libraries).

Duck typing: "if it walks like a duck…" — behavior, not declared type, decides usability. Pythonic style pairs it with EAFP (Easier to Ask Forgiveness than Permission): just try, catch the exception.

# LBYL — look before you leap (racy, verbose)
if hasattr(obj, "read") and callable(obj.read):
    data = obj.read()

# EAFP — Pythonic (atomic, race-free)
try:
    data = obj.read()
except AttributeError:
    data = None
💡 EAFP also avoids TOCTOU races (file deleted between check and open) — exceptions are cheap when rare, costly in hot loops.
  • == calls __eq__ → value equality.
  • is compares identity (same object in memory, i.e. id()).
  • CPython caches small ints -5…256 and some strings → (256+1) is 257 may be False while 255 is 255 is True. Never rely on it.
a = 1000; b = 1000
a == b  # True  — values equal
a is b  # False (usually) — distinct objects!
x = None
x is None  # ✅ correct — singletons compared by identity
⚠️ Rule: is only for singletons (None, True/False, sentinels). Everything else → ==.

Falsy: None, False, 0/0.0/0j, "", [], {}, (), set(), range(0). Everything else is truthy. Resolution order: __bool__() → else __len__() == 0 → else True.

class Bag:

    def __len__(self): return len(self.items)

bool(Bag([]))  # False — via __len__

Functions, classes, modules, even None are heap objects with a type pointer and refcount (see Q65). Consequences:

  • Introspection everywhere: type(x), dir(x), x.__dict__, inspect module.
  • Monkey-patching: rebind attributes at runtime (powerful, dangerous).
  • Uniform protocol model: dunder methods (__len__, __iter__) instead of interfaces.
  • Cost: even 1 is a 28-byte PyLongObject — hence numpy for numerics.

Data Types & Internals
Q11 – Q20
  • Semantics: lists = homogeneous sequences; tuples = heterogeneous records (hence unpacking, divmod returns, dict keys).
  • Performance: tuples are smaller, iterate slightly faster, and construction can be constant-folded.
  • Hashability: tuple of hashables is hashable → dict keys, set members, lru_cache args.
  • Cowboy detail: CPython keeps a tuple freelist (buffered reuse) and over-allocates lists on growth (amortized O(1) append).
import sys
sys.getsizeof([1,2,3])  # 88 — over-allocated buffer
sys.getsizeof((1,2,3))  # 64 — exact fit
  • Open-addressing hash table: hash(key) → slot; collisions resolved by probing (perturbation scheme).
  • Since 3.6 (guaranteed 3.7): compact + insertion-ordered — dense entry array in insertion order + sparse index of slots. Iteration is cheap and ordered; memory dropped ~25%.
  • Resize at 2/3 load (sizes 8, 16, 32…); deletion inserts a dummy to keep probe chains intact.
  • Keys must be hashable + equality-stable; equal keys must hash equal (1 == True, same hash — they collide as one key!).
⚠️ Never mutate a dict during iteration (RuntimeError) — iterate over list(d). And never use a mutable default as a key.
  • O(1) membership tests — x in big_set vs O(n) list scan; the classic dedup: list(dict.fromkeys(items)) (ordered) or list(set(items)).
  • Set algebra: | union, & intersection, - difference, ^ symmetric difference — expressive diffing of collections.
  • frozenset = immutable + hashable → dict keys, set elements, lru_cache-friendly snapshots.
seen = set()
seen.add((1, 2))   # tuple ok
# seen.add([1, 2])  → TypeError: unhashable
  • Immutable + Unicode (flexible representation: 1/2/4 bytes per char — PEP 393). Every "modification" builds a new string → always "".join(...) in loops.
  • Interning: identifiers/literals may share one object (sys.intern() forces it — big win for millions of repeated tokens from parsers).
  • Formatting: % (legacy), str.format (verbose), f-strings (fastest — compiled to FORMAT_VALUE, support = debug and format specs).
name, n = "ada", 42
f"{name=} {n:05d}"  # "name='ada' 00042"

  • int = variable-length array of 30-bit "digits" (PyLongObject) → no overflow, but big-int math is O(n) in digits. 10**1000000 works, slowly.
  • 3.11+ safety cap: int↔str conversion limited to 4300 digits by default (sys.set_int_max_str_digits) — blocks DoS via giant parses.

Contract: a == b ⇒ hash(a) == hash(b), stable for the object's lifetime as a key.

  • Defining __eq__ without __hash__ sets __hash__ = None → instances become unhashable. Opt back in explicitly.
  • Mutable fields in __hash__ = time bomb (mutate → lost in dict). Hash on immutable identity instead.
  • @dataclass(frozen=True) / eq=True auto-generates a consistent pair.
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, o): return (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))
  • Comprehensions have their own scope (3.x): loop var doesn't leak — except the walrus := deliberately binds outside.
  • [...] list, {...} set/dict, (...) generator (lazy — one-shot!).
  • Nested loops read left-to-right; conditions filter. Prefer them over map/filter+lambda for readability.
squares = [x*x for x in range(10) if x % 2 == 0]
total = sum(x*x for x in range(10**7))  # genexpr — no 80MB list
  • seq[start:stop:step] → calls __getitem__ with a slice object. Out-of-range bounds are clipped, never errors.
  • Negative step reverses: s[::-1]. s[:] = shallow copy.
  • Slice assignment mutates in place: a[1:3] = [7, 8, 9] (even resizes!). del a[::2] deletes every other.
  • numpy/pandas extend this to multi-dimensional slicing — same protocol underneath.
  • None – the null object; always compare with is None.
  • Ellipsis (...) – placeholder (stub bodies, numpy multi-axis slicing a[..., 0]).
  • NotImplemented – return from dunders to let Python try the reflected operation (a.__add__(b) → b.__radd__(a)). Never raise it — return it.
  • Custom sentinels: _MISSING = object() + is checks beat magic defaults.

Functions, Scope & Decorators
Q21 – Q32

Functions are objects: assign, pass, return, store in containers. This single fact powers callbacks, decorators, strategies, and registries.

handlers = {}
def route(path):
    def deco(fn):
        handlers[path] = fn   # functions as registry values
        return fn
    return deco

@route("/ping")
def ping(): return "pong"   # = ping = route("/ping")(ping)

Name lookup: Local → Enclosing → Global → Builtins. Assignment binds locally unless declared otherwise.

x = "global"
def outer():
    x = "enclosing"
    def inner():
        nonlocal x   # rebind outer's x (closure write!)
        x = "changed"
    inner()
    return x       # "changed"

def f():
    global x      # rebind module-level x
⚠️ Reading a global then assigning it in one function = UnboundLocalError (compiler marks it local for the whole scope).

A closure captures variables (cells), not values — looked up at call time. Loop-created closures all see the final value:

funcs = [lambda: i for i in range(3)]
[f() for f in funcs]  # [2, 2, 2] — not [0, 1, 2]!

# Fix: bind as a default (evaluated at def time)
funcs = [lambda i=i: i for i in range(3)]
[f() for f in funcs]  # [0, 1, 2] ✅
ℹ️ Under the hood: co_cellvars/co_freevars + LOAD_DEREF (see Q99). Inspect with fn.__closure__.

Defaults evaluate once at def time and are shared across calls:

def add(item, bag=[]):   # ❌ one list forever
    bag.append(item)
    return bag

add(1)  # [1]
add(2)  # [1, 2] — surprise!

def add(item, bag=None):  # ✅ sentinel pattern
    if bag is None: bag = []
    bag.append(item)
    return bag
💡 Same root cause as Q23: def executes once, eagerly. Inspect via add.__defaults__.
  • Definition def f(a, *args, k, **kw): positional overflow → tuple, keyword overflow → dict.
  • Call f(*lst, **d): unpack any iterable/mapping into arguments.
  • Bare * forces keyword-only args after it; / forces positional-only before it (C-API style, fast).
  • Forwarding pattern preserves signatures: def wrap(*a, **k): return f(*a, **k).
def f(a, /, b, *, c): ...
f(1, 2, c=3)   # ✅  f(a=1) → TypeError

@deco = rebinding: f = deco(f) at def time. Decorator with args = factory returning the real decorator (two nesting levels).

import functools, time
def timed(fn):
    @functools.wraps(fn)  # preserves __name__/__doc__/__wrapped__
    def inner(*a, **k):
        t = time.perf_counter()
        try: return fn(*a, **k)
        finally: print(fn.__name__, time.perf_counter() - t)
    return inner

  • Any callable taking the class and (usually) returning it: @dataclass, @functools.total_ordering, registry patterns.
  • Runs once at class creation — perfect for validation, method injection, registration.
  • Heavier alternative: metaclasses (Q41) control creation itself; decorators only post-process.
def singleton(cls):
    inst = {}
    def get(*a, **k):

lambda is a single expression — no statements, no annotations, always anonymous (though assignable). It exists for tiny throwaway callables (key=, sorted); anything needing statements deserves def.

pairs = [(1, "b"), (2, "a")]
sorted(pairs, key=lambda p: p[1])  # sort by 2nd element
# PEP 8: never assign lambda to a name — use def instead
  • Each call pushes a C-level frame; unbounded recursion segfaults the C stack → CPython caps at sys.getrecursionlimit() (1000) with RecursionError.
  • No tail-call optimization (deliberate — Guido: tracebacks must stay complete).
  • Raising the limit is usually wrong: rewrite iteratively or with an explicit stack; deep JSON/pickle structures are the classic victims.
  • lru_cache(maxsize=…) – memoizes on hashable args; exposes cache_info()/cache_clear(). Never cache unbounded on unbounded inputs (memory leak) — and never with unhashable/mutable args.
  • partial – freeze leading args: run = partial(subprocess.run, check=True).
  • singledispatch – type-based overloading (poor man's multimethods) for the first arg.
@functools.lru_cache(maxsize=1024)
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)
  • Nothing by default — stored in fn.__annotations__, ignored by the interpreter (except evaluated eagerly at def time, unless from __future__ import annotations stringifies them).
  • Enforced by external checkers (mypy, pyright) and runtime validators (pydantic, attrs, beartype).
  • typing arsenal: Optional/X | None, Protocol (structural), TypeVar/ParamSpec (generics), overload, TypedDict, Literal.

wraps copies __module__, __name__, __qualname__, __doc__, __dict__ and sets __wrapped__. Without it: broken tracebacks, wrong help(), stacked decorators lose metadata, and inspect.signature follows __wrapped__ chains to show the real signature.

OOP, Dunders & Metaclasses
Q33 – Q44

self is just the conventional name for the explicitly passed instance. Methods are plain functions stored on the class; attribute access binds them via the descriptor protocol into bound methods (function + instance).

class A:
    def m(self): return self
a = A()
a.m()        # bound: A.m(a)
A.m(a)       # identical unbound call
type(a.m)    # <class 'method'>
  • __new__(cls, …) – creates the instance (static method, returns the object). Rarely overridden — singletons, immutable subclassing (int/str/tuple need it since __init__ can't set their value), custom allocation.
  • __init__(self, …) – initializes the already-created instance. Returns nothing.
  • Call chain: A(…) → type.__call__ → cls.__new__(cls,…) → isinstance check → obj.__init__(…).

Method Resolution Order = the class search path, computed by C3 linearization (monotonic, preserves local precedence + base order). Inspect with Cls.mro().

Any object with __get__/__set__/__delete__. Attribute lookup calls the descriptor instead of returning it:

  • Data descriptors (__set__ present: property, slots) beat instance dict.
  • Non-data (plain functions → bound methods, classmethod, staticmethod) lose to instance dict.
  • Precedence: data descriptor → instance __dict__ → non-data descriptor/class attr.
class Typed:  # validated-attribute descriptor
    def __set_name__(self, owner, name): self.name = name
    def __get__(self, obj, cls): return obj.__dict__[self.name]
    def __set__(self, obj, v):
        if not isinstance(v, int): raise TypeError
        obj.__dict__[self.name] = v
  • Replaces per-instance __dict__ with a fixed C-array → ~40–50% less memory per object, faster attribute access.
  • Costs: no dynamic attributes, no weakrefs (unless "__weakref__" listed), multiple inheritance needs every base slotted, pickling needs care.
  • Worth it for millions of small objects (AST nodes, rows, particles). Also pairs with @dataclass(slots=True).

A metaclass is the class of a class: type(cls). Class creation = Meta(name, bases, namespace); customize via __new__/__init__/__call__ (the last intercepts instantiation).

  • Justified: ORMs (Django models), ABCs/enums, API registration, interface enforcement.
  • Prefer first: class decorators, __init_subclass__ (runs on subclassing — covers 90% of metaclass use!), __set_name__.
class Registry(type):
    plugins = {}
    def __new__(m, name, bases, ns):
        cls = super().__new__(m, name, bases, ns)
        if name != "Base": m.plugins[name] = cls
        return cls
  • ABC (abc.ABC + @abstractmethod) – nominal: must inherit; instantiation blocked until all abstracts implemented. Virtual subclasses via register().
  • Protocol (typing.Protocol) – structural: "has these members" suffices, no inheritance. Static-checker feature (runtime only with @runtime_checkable, and then only member presence).
  • Rule: ABCs for frameworks needing runtime enforcement; Protocols for flexible duck-typed APIs.
  • Mixin = small behavior class (no state, no __init__ args), designed to compose: class View(LoginMixin, CacheMixin, Base).
  • Every __init__ must call super().__init__(**kwargs) and forward unknowns — the chain walks the MRO exactly once.
  • Order matters: put mixins leftmost, most-specific first.

Iterators, Generators & Context Managers
Q45 – Q54
  • Iterable: has __iter__ returning a fresh iterator — lists, dicts, files.
  • Iterator: has __iter__ (returns self) and __next__ (raises StopIteration when done).
  • for = iter(x) then next() until StopIteration. Iterators are single-pass; re-looping an exhausted generator silently yields nothing (classic bug!).
class Count:
    def __init__(self, n): self.n, self.i = n, 0
    def __iter__(self): return self
    def __next__(self):
        if self.i >= self.n: raise StopIteration
        self.i += 1; return self.i

Any function with yield is a generator factory: calling it returns a generator without running a line. Each next() resumes the saved frame (instruction pointer + locals) until the next yield.

  • Lazy + O(1) memory: stream terabytes through constant RAM.
  • gen.send(v) injects a value as the yield's result; throw()/close() drive exceptions and cleanup.
  • Introspect: gi_frame, gi_running, inspect.getgeneratorstate.
def gen():
    x = yield 1   # yields 1; next send() becomes x
    yield x + 1
g = gen(); next(g)  # 1
g.send(10)          # 11
  • Delegates the whole protocol: values, send(), throw(), close() pass through to the sub-generator.
  • Captures the sub-generator's return value (surfaced via StopIteration(value), PEP 380).
  • Foundation of pre-async/await coroutines (@asyncio.coroutine era).
def sub():
    yield 1; return "done"
def main():
    result = yield from sub()  # "done"
    yield result

Chain single-purpose stages: source → filter → transform → sink. Each pulls lazily; memory stays flat.

def lines(path):
    with open(path) as f:
        for line in f: yield line

for e in (r for r in lines("10gb.log") if "ERROR" in r):
    ...  # ~KB of RAM regardless of file size
⚠️ One-shot! Re-create or use itertools.tee (buffers!). Debug laziness with itertools.islice.
  • chain (flatten), islice (lazy slicing), count/cycle/repeat (infinite streams).
  • groupby (needs pre-sorted input!), pairwise (3.10+), batched (3.12+).
  • product/permutations/combinations (beware combinatorial explosion), accumulate, zip_longest.
  • more-itertools: chunked, first_true, collapse.
  • Protocol: __enter__ (value bound by as) + __exit__(exc_type, exc, tb). Returning True suppresses the exception.
  • @contextlib.contextmanager: code before yield = enter, after = exit (wrap post-yield in try/finally!).
  • Stacking: with a, b: or ExitStack for a dynamic number of contexts.
from contextlib import contextmanager
@contextmanager
def timer(name):
    t = time.perf_counter()
    try: yield
    finally: print(name, time.perf_counter() - t)
  • Return truthy → swallowed (prefer contextlib.suppress(ValueError) over hand-rolled).
  • Return falsy/None → re-raised after __exit__; raising anew inside chains it (__context__ → "During handling…" tracebacks).
  • raise … from err sets explicit __cause__; from None hides context for cleaner library errors.
  • async for drives __aiter__/__anext__ — streaming sockets, queues, paginated APIs.
  • async with drives __aenter__/__aexit__ — asynchronously acquired locks, connections, transactions.
  • Async generators: async def containing yield; consume with async for or async comprehensions.

Pre-3.7, a stray StopIteration inside a generator body silently terminated the loop — hiding bugs. Now it becomes RuntimeError: generator raised StopIteration. Fix: return instead of raising.

def bad():
    yield from []       # fine — delegation
    raise StopIteration  # ❌ RuntimeError since 3.7
  • Generator-based (3.3–3.7): @asyncio.coroutine + yield from — reused generator machinery for event loops.
  • Native (3.5+): async def/await — dedicated CO_COROUTINE objects; no yield inside (use async generators).
  • Same suspension idea, cleaner semantics: await pauses only at awaitables (coroutines, Tasks, Futures), making scheduling explicit.

The Import System
Q55 – Q64
  1. sys.modules cache hit → return immediately (imports are singletons!).
  2. Finders (sys.meta_path: builtin → frozen → path-based) locate a spec (name, loader, origin).
  3. Create the module, insert into sys.modules first (partially initialized — this is what lets circular imports resolve at all).
  4. Loader executes the code in the module namespace (SourceFileLoader compiles source; ExtensionFileLoader dlopens .so).
  5. Bind the name in the importing namespace.
ℹ️ Re-importing is nearly free (dict lookup). Forcing re-execution needs importlib.reload() — with caveats (Q56).
  • sys.modules is the live registry: inject test doubles (sys.modules["requests"] = fake), detect double-imports (same file as mod and pkg.mod = two module objects, breaking isinstance).
  • reload(mod) re-executes in the existing namespace: old classes/functions linger, from x import y bindings go stale, C extensions usually can't reload.
  • Fix double-imports with absolute imports + launching via python -m.
  1. Script directory (or cwd for REPL; -m uses cwd instead — classic gotcha).
  2. PYTHONPATH entries.
  3. Stdlib + site-packages (plus .pth additions, venv paths).

Debug with python -m site. Naming your file random.py hijacks step 1 and shadows the stdlib — the infamous beginner bug.

  • Absolute (from pkg.sub import x) – always preferred; unambiguous, grep-able.
  • Explicit relative (from . import sib) – intra-package only, resolved against __package__.
  • Running a submodule as a script (python pkg/mod.py) breaks relatives (__package__ is None) → run python -m pkg.mod.

A imports B, B imports A: the second import finds a partially initialized module → ImportError/missing attribute.

  • Defer: move the import inside the function.
  • Restructure: extract shared code to a third module.
  • Import the module, not names (import b; b.func() resolves at call time).
  • TYPE_CHECKING guard + string annotations for type-only cycles.
  • Regular package (with __init__.py): single directory, init runs on first import — version, re-exports (__all__), lazy __getattr__ (PEP 562).
  • Namespace package (no init): spans multiple sys.path directories — plugins, monorepos, distro-split packages.
  • Keep __init__.py light: heavy imports slow every submodule import and invite cycles.
  • Direct execution sets __name__ == "__main__"; import sets the module name. The guard separates library from script behavior.
  • python -m pkg.mod runs with package context (relatives work) and cwd on sys.path — the correct launcher for package code and tools.
  • python -m x also executes __main__.py in packages/dirs/zipapps — how pip, venv, and zipapps run.
  • Lazy (function-level) imports: heavy/optional deps (torch, pandas), cycle-breaking, fast CLI startup. Cost: hidden deps (negligible lookup — sys.modules hit).
  • if TYPE_CHECKING: import x + quoted annotations: visible to checkers, never imported at runtime — zero-cost, cycle-free.
  • Detect optional deps: importlib.util.find_spec("torch") is not None.
  • ExtensionFileLoader dlopen()s the shared object, then calls its PyInit_<name> entry point (multi-phase init per PEP 489 in modern extensions).
  • Filenames carry ABI tags (mymod.cpython-311-x86_64-linux-gnu.so) — wrong interpreter → ImportError; hence version-specific wheels.
  • They live in sys.modules like any module but generally cannot be reloaded.

Memory Model & Garbage Collection
Q65 – Q76

Every object starts with PyObject: a reference count + a type pointer (variable-size objects add ob_size). The type pointer is how type(x), method lookup, and every dunder dispatch work — pure C-level indirection, no vtables in Python code.

import sys
sys.getsizeof(1)      # 28 — int object header + digits
sys.getsizeof([])     # 56 — list header (no items yet)
sys.getsizeof("")      # 49 — str header + nul
💡 This is why "just an int" costs 28 bytes — and why numpy arrays (raw C buffers + one header) win 10–50× on numerics.
  • Refcounting (primary): count drops to zero → deallocated immediately (deterministic destruction → reliable with/file closing, unlike Java).
  • Cyclic GC (backup): finds reference cycles refcounting can't (a↔b). Only container types participate (tracked by GC).
  • Generations 0/1/2: survivors promote; gen0 collected often, gen2 rarely. Thresholds tunable via gc.set_threshold().
import gc
gc.get_threshold()   # (700, 10, 10) defaults
gc.collect(2)          # force full collection → returns unreachable count
  • gc.get_objects() — every tracked object (huge; filter by type).
  • gc.get_referrers(x) / get_referents(x) — who keeps this alive? (frames in the output are the debugger's own — exclude them).
  • tracemalloc – where memory was allocated: start() → snapshot → compare_to() top diffs by traceback.
  • Growth check: len(gc.get_objects()) or per-type counts across requests — monotonic growth = leak.
import tracemalloc
tracemalloc.start()
... workload ...
snap = tracemalloc.take_snapshot()
for s in snap.statistics("traceback")[:5]: print(s)
  • Small ints −5…256 preallocated at startup; a = 100 twice → same object.
  • String interning: identifiers + explicit sys.intern() — dedups millions of repeated tokens (parsers, CSV columns).
  • Freelists: dead lists, tuples, frames, ints recycled into per-type free lists instead of malloc/free churn.
  • List over-allocation: appends amortized O(1) via geometric growth (also why a shrunk list keeps memory — use list.clear() + realloc patterns or array module).
  • getsizeof counts only the container shell, not referents: getsizeof([1]*1000) misses all 1000 ints (~28 KB).
  • Recursive walkers (pympler asizeof, sys.getsizeof + manual traversal) approximate totals.
  • tracemalloc attributes Python allocations to source lines — best for "what grew?".
  • OS-level truth (RSS): resource.getrusage, psutil.Process().memory_info() — includes fragmentation, allocator arenas, C-side (numpy!) memory Python can't see.
  • copy.copy: new outer object sharing children; honors __copy__.
  • copy.deepcopy: recursive clone with a memo dict mapping id(old)→new — shared subobjects stay shared, cycles terminate.
  • Customize via __deepcopy__(self, memo) (e.g. skip un-copyable locks/sockets, re-create them).
  • Immutable atoms (int/str/tuple-of-immutables) are returned as-is — no wasted copies.

weakref.ref(obj, callback) observes without keeping alive; dies automatically when the referent does. Use cases: caches (WeakValueDictionary), parent back-pointers (avoid cycles), observers/listeners.

import weakref
cache = weakref.WeakValueDictionary()
class Node:
    def __init__(self, parent=None):
        self.parent = weakref.ref(parent) if parent else None
        # child → parent never keeps parent alive ✅
⚠️ Not everything is weakref-able: plain int/str/tuple/list/dict refuse; user classes work (unless __slots__ without "__weakref__").
  • __del__ (finalizer) runs at deallocation — but in cycles order is undefined and exceptions are swallowed (printed to stderr).
  • Resurrection: __del__ storing self somewhere revives the object; pre-PEP 442 this broke the collector (objects finalized twice or never).
  • PEP 442 (3.4+): safe finalization ordering; still — prefer weakref.finalize or context managers over __del__.

Objects exposing the buffer protocol (bytes, bytearray, array, mmap, numpy) share raw memory without copying. memoryview slices/casts those buffers as typed views.

buf = bytearray(10_000_000)
mv = memoryview(buf)
chunk = mv[100:200]   # view — zero bytes copied
chunk[0] = 255         # writes through into buf!
ints = mv.cast("i")      # reinterpret as int32 array
💡 This is the foundation of numpy↔PIL↔socket zero-copy pipelines — and of Q112 (buffers in C).
  • Normal instances: attribute dict (__dict__) — flexible, ~100+ bytes overhead per object plus the dict itself.
  • __slots__: fixed C-array offsets, no dict (see Q40) — ~40–50% smaller, faster access.
  • Middle ground: keys-sharing dicts (CPython 3.3+ — instances of one class share key storage), __getattr__-backed lazy attrs, flyweight for repeated values.
  • Strings immutable → each += copies → O(n²) total. Always "".join(chunks) (O(n)), or io.StringIO for incremental writers.
  • Nuance: CPython has an in-place overallocation trick when refcount==1 (s += x can extend) — unreliable, don't depend on it; PyPy/Jython lack it entirely.
  • Same rule for bytes: accumulate in bytearray, convert once.
  • CPython's obmalloc carves 256 KB arenas → pools → blocks for small objects; large objects go to malloc directly. Freed arenas may stay mapped → RSS rarely shrinks (fragmentation, not a leak!).
  • MALLOC_TRIM_THRESHOLD_ / PYTHONMALLOC=malloc trade speed for return-to-OS behavior; gc.collect() frees objects, not necessarily pages.
  • numpy/C extensions allocate outside obmalloc — invisible to tracemalloc, visible in RSS. Diagnose with_counts + RSS together.

GIL & Concurrency
Q77 – Q88

The Global Interpreter Lock: a mutex allowing only one thread at a time to execute Python bytecode in a process. It exists because:

  • Refcount safety — every operation touches refcounts; fine-grained locking would be slow and bug-prone.
  • C-extension simplicity — decades of extensions assume single-threaded Python access.
  • Single-threaded programs (the majority) pay ~zero cost.
💡 The GIL is a CPython implementation detail, not a language feature — Jython/IronPython/GraalPy never had one.

  • Races are real: the GIL switches between bytecodes (5 ms interval, sys.getswitchinterval()), so count += 1 (LOAD→ADD→STORE) interleaves. Only single bytecodes are atomic-ish.
  • queue.Queue is thread-safe (condition-variable guarded) — the default handoff; raw shared state needs Lock/RLock.
  • Daemon threads die with the program (no join, no cleanup) — fine for watchdogs, never for writes you must flush.

  • fork (Unix default pre-3.14): inherits memory copy-on-write; fast but unsafe with threads (only async-signal-safe between fork/exec — hence macOS/3.8+ default spawn).
  • spawn: fresh interpreter re-importing your module → needs if __name__ == "__main__" guard + picklable targets/args.
  • IPC: Queue/Pipe (pickled), shared_memory/Value/Array (raw, fast), Managers (slow RPC).
  • I/O-bound + shared memory wanted → ThreadPool (cheap startup, shared objects).
  • CPU-bound → ProcessPool (bypasses GIL; pickling cost amortized over heavy work).
  • Many tiny CPU tasks → neither: batch into chunks (chunksize) or vectorize (numpy) — per-task overhead dominates otherwise.
  • max_workers: threads ≈ dozens–hundreds for I/O; processes ≈ os.cpu_count().
  • One thread, one event loop: runs coroutines, switching only at await points — no preemption, no races between awaits, no GIL benefit needed (it never needed threads).
  • async def = coroutine; await x = suspend until x completes; asyncio.create_task() schedules concurrent execution; asyncio.gather joins results.
  • Blocking calls freeze the whole loop — offload with asyncio.to_thread; CPU work with run_in_executor(process_pool).

CPython Pipeline, Bytecode & dis
Q89 – Q102
  1. Parse: tokenizer + PEG parser → AST (ast.parse; view with ast.dump).
  2. Symbol tables + CFG: scope analysis, basic blocks, control-flow graph.
  3. Codegen: AST → bytecode code objects (nested: module, function, comprehension each get one).
  4. Optimize: peephole/AST opts (Q94), then marshal into .pyc.
  5. Execute: ceval loop interprets bytecode against frames; 3.11+ specializes hot opcodes adaptively.
  • Bytecode: compact instruction stream for the ceval VM (opcodes + opargs), stored in code.co_code with constants/names in co_consts/co_names/co_varnames.
  • .pyc: marshalled code objects in __pycache__/mod.cpython-311.pyc — a cache only, still version-specific.
  • Validation: source mtime+size by default; PYTHONPYCACHEPREFIX, hash-based pycs (--check-hash-based-pycs) for read-only deploys.
  • Version skew → silently recompiled. Never ship only pyc (debugging, auditing, and cross-version pain).

ceval is a value-stack machine: opcodes push/pop values; no registers in the classic model.

  • LOAD_FAST (locals array) vs LOAD_GLOBAL (dict/namespace lookup — slower!) vs LOAD_DEREF (closure cells) vs LOAD_CONST.
  • BINARY_OP pops two, pushes result (specialized per type at runtime in 3.11+).
  • RETURN_VALUE / YIELD_VALUE hand the top of stack back.
  • Why local-variable micro-optimization works: LOAD_FAST is array indexing; LOAD_GLOBAL is dict + version checks.
  • PyFrameObject: code object + value stack + block stack + instruction pointer + fast-locals array + back-pointer (call chain).
  • Inspect live: inspect.currentframe(), f_code.co_name, f_lasti (bytecode offset!), f_back (caller).
  • Tracebacks = linked frame list + line-number table (co_linetable); generators/coroutines keep their frames alive between suspensions (that's the magic of Q46).
  • 3.11+ frames are heap-allocated lazily and smaller — part of the Faster CPython wins.

  • python -O: strips assert statements, sets __debug__ = False. -OO additionally drops docstrings.
  • Never assert for runtime validation (user input, prod checks) — -O deletes them. Asserts are for impossible-state documentation in dev/tests.
  • 3.11+ calling convention: push callable + args, PRECALL/CALL (specialized: CALL_BOUND_METHOD_EXACT_ARGS, CALL_PY_EXACT_ARGS…).
  • Vectorcall (PEP 590): C-level fast path passing a C array of args — how numpy/C functions avoid tuple/dict packing.
  • *args/**kwargs calls build tuple/dict first (BUILD_TUPLE/BUILD_MAP) — measurably slower than plain calls; hot paths avoid them.
  • Bound-method optimization: LOAD_METHOD/CALL_METHOD skip bound-method allocation for obj.method(x).
  • 3.11+: zero-cost exceptions — no setup opcodes on entry; an exception table maps instruction ranges → handlers. try blocks cost nothing when no exception fires.
  • Raising walks the table, unwinds frames, matches except types; finally compiles to duplicated cleanup + re-raise paths.
  • Cost model: entering try ≈ free; raising is expensive (traceback construction) → EAFP is for rare failures, not hot-loop control flow.

Nested def compiles to: build defaults/annotations tuple → LOAD_CLOSURE (cell refs) → BUILD_TUPLE → MAKE_FUNCTION (binds code + closure) → STORE_FAST.

  • import a.b → IMPORT_NAME a.b (calls __import__ machinery from Q55) then binds top name.

The contract behind 90% of C-extension bugs:

  • New reference (you own it, must Py_DECREF): constructors (PyLong_FromLong), PyObject_Call, PySequence_GetItem(!).
  • Borrowed (owner keeps it, INCREF if you store it): PyList_GetItem, PyDict_GetItem, PyTuple_GET_ITEM, METH_O args.
  • Return protocol: return owned ref on success, NULL + set exception on failure (PyErr_SetString).
  • Leak check: sys.gettotalrefcount() (debug build) or tracemalloc + repeat-call RSS growth.
⚠️ PyList_GetItem (borrowed) vs PySequence_GetItem (new) — same data, opposite ownership. Read the docs per function, every time.
  • Extension functions run with the GIL held. Release around pure-C blocking work (Q88): Py_BEGIN_ALLOW_THREADS … Py_END_ALLOW_THREADS — touch no Python objects inside.
  • Calling back into Python from a foreign thread: acquire with PyGILState_Ensure(), release with PyGILState_Release().
  • Free-threaded builds (Q84): same API, but your C code must actually be thread-safe now — the GIL no longer serializes your bugs away.

PyCapsule wraps a raw void* + name tag + destructor in a Python object. Producer and consumer agree on the name; mismatched names → ValueError instead of memory corruption. The destructor frees/closes the resource when the capsule dies — RAII across the boundary.

  • Exporter keeps memory alive while views exist (locked via its own refcount) — safe zero-copy.
  • This is how numpy.frombuffer(bytearray), PIL, and socket code share gigabytes without memcpy — the C twin of Q73's memoryview.
