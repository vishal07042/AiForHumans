Networking Fundamentals
Q1 – Q9

A computer network is a set of devices (hosts, routers, switches) connected via links that communicate using agreed protocols to share resources and data.

  • Nodes – PCs, phones, servers, printers, IoT devices.
  • Links – wired (copper/fiber) or wireless (radio).
  • Protocols – TCP/IP, DNS, HTTP, DHCP; they define format, addressing, and rules.
  • Services – file sharing, email, web, streaming, remote access.
💡 Interview one-liner: "A network moves bits between addressed endpoints reliably, using layered protocols."
TypeScopeExampleTypical Tech
PAN~10 m, one personPhone + earbuds + watchBluetooth, USB
LANRoom → campusOffice / home networkEthernet, Wi-Fi, switches
MANCityCity fiber ring, campus interconnectMetro Ethernet, MPLS
WANCountry / globalISP backbone, InternetMPLS, leased lines, BGP

Key trade-off: as scope grows, bandwidth typically drops, latency rises, and cost/complexity increase.

  • Star – all nodes connect to a central switch. Easy to manage; switch is a single point of failure. Dominant today.
  • Mesh (full/partial) – redundant paths; used in WAN backbones and data centers. Expensive.
  • Ring – each node connects to two neighbors (SONET/FDDI legacy). One break can be protected by dual ring.
  • Bus – single shared cable (old Ethernet coax). Cheap but one fault kills all; collisions.
  • Hub-and-spoke / Tree – branches off a core; typical enterprise LAN hierarchy (access → distribution → core).
💡 Modern LANs are physical star + logical hierarchy; WANs are partial mesh.

  • Unicast – one sender → one receiver (most traffic: web, SSH). Address: single host IP.
  • Broadcast – one → all hosts on a subnet (ARP requests, DHCP discover). IPv4 255.255.255.255; routers do NOT forward it.
  • Multicast – one → subscribed group (IPTV, OSPF hellos to 224.0.0.5). Range 224.0.0.0/4; needs IGMP/PIM.
  • Anycast – one → nearest of several identical servers (DNS roots, CDNs). Same IP announced from many places via BGP.
ℹ️ IPv6 removed broadcast entirely — it uses multicast (e.g., solicited-node) instead.

A protocol is a formal rule set for communication: message format, addressing, sequencing, error handling, and teardown.

  • Syntax – bit/field layout (headers).
  • Semantics – what each message means (SYN = "open connection").
  • Timing – timeouts, retransmissions, ordering.

Good protocols are layered, interoperable (open standards/RFCs), extensible (version fields, options), and handle failure explicitly.

Connection-oriented (TCP)Connectionless (UDP/IP)
SetupHandshake before dataNo setup — just send
ReliabilityAcks, retransmission, orderingBest-effort; app handles loss
OverheadHigher (state, headers)Minimal
UseWeb, files, emailDNS, VoIP, gaming, streaming
  • Simplex – one direction only (keyboard → PC, TV broadcast).
  • Half-duplex – both directions, one at a time (walkie-talkie, legacy hubs, Wi-Fi).
  • Full-duplex – both directions simultaneously (modern switched Ethernet with separate TX/RX pairs).
⚠️ Duplex mismatch (one side half, other full) causes collisions, late collisions, and terrible throughput — check with ethtool / switch logs.

💡 The Internet runs on TCP/IP in practice; OSI is the reference vocabulary interviewers expect you to use.

Each layer wraps the upper-layer data with its own header (and sometimes trailer) on send, and strips it on receive.

# Sending down the stack:
Data → TCP header + Data             (segment)
     → IP header + TCP + Data         (packet)
     → Ethernet header + IP + FCS trailer  (frame → bits)

PDU names: L4 segment (TCP) / datagram (UDP) → L3 packet → L2 frame → L1 bits.

DeviceLayerForwards based on
Hub / RepeaterL1Bits — repeats everything (one collision domain)
Switch / BridgeL2MAC table (CAM)
Router / L3 switchL3IP routing table (longest prefix match)
Firewall / NATL3–L4 (some L7)IP/ports/state; NGFW inspects apps
Load balancer / Proxy / WAFL4–L7TCP + HTTP content
  • Common language – "L2 loop" vs "L7 bug" instantly localizes a problem.
  • Troubleshooting order – always verify L1 → L2 → L3 before blaming the app.
  • Design clarity – each layer can evolve (fiber → Wi-Fi 6) without rewriting TCP or HTTP.
  • Interviews/certifications – CCNA and most panels still frame questions in OSI terms.

L1 converts bits to signals: voltage levels, light pulses, or radio waves. Defines connectors, pinouts, frequencies, and modulation.

  • Copper: Cat5e/6/6a (1/10 Gbps), RJ45, max ~100 m per run.
  • Fiber: single-mode (long haul) vs multi-mode (data center); uses SFP/SFP+ optics.
  • Wireless: RF channels, modulation (QAM), MIMO.
⚠️ L1 faults (bad cable, dirty fiber, wrong transceiver, no link light) cause everything above to fail — check link lights first.

The Data Link layer (L2) splits into two IEEE 802 sublayers:

  • MAC (lower) – hardware addressing (48-bit MAC), media access (CSMA/CD, CSMA/CA), framing. Implemented in NIC/switch ASICs.
  • LLC (upper) – multiplexing L3 protocols over one link (Ethertype: 0x0800 = IPv4, 0x86DD = IPv6), flow control, optional reliability.
  • Presentation (L6) – TLS encryption, JPEG/MPEG codecs, character encoding (UTF-8), compression (gzip). Anything that converts "app data" ↔ "wire format".
  • Session (L5) – SIP call setup, NetBIOS sessions, RPC bindings, database connections, SSH channels; checkpointing and re-establishing interrupted dialogs.
💡 In TCP/IP these collapse into the Application layer — but naming them helps explain where TLS or codecs sit.
  1. App builds data → TCP adds ports → IP adds src/dst IP → Ethernet adds src/dst MAC (gateway MAC if remote).
  2. Switch reads dst MAC, looks up CAM table, forwards out the right port (floods if unknown).
  3. Router strips L2 frame, reads dst IP, longest-prefix lookup, decrements TTL, re-frames with new L2 header toward next hop.
  4. Repeat per hop; final host strips headers bottom-up and delivers to the socket.
ℹ️ MAC addresses change every hop (hop-to-hop); IP addresses stay end-to-end (unless NAT).

Subnetting splits one large network into smaller subnets by borrowing host bits for the network portion.

  • Why: limit broadcast domains, improve security/isolation, efficient address use, simpler routing (summarization).
  • How: apply a longer mask. 10.0.0.0/8 → four /10s, or 256 /16s, or 65,536 /24s.
  • Each subnet has a network address (all host bits 0), broadcast (all host bits 1), and usable hosts between them.

CIDR (Classless Inter-Domain Routing) writes a network as IP/prefix-length where the number = count of network bits.

192.168.1.0/24  → mask 255.255.255.0 → 256 addrs, 254 usable
10.0.0.0/8    → mask 255.0.0.0 → ~16.7M addrs
172.16.5.64/26 → mask 255.255.255.192 → 64 addrs, 62 usable
💡 Usable hosts = 2^(32 − prefix) − 2 (minus network + broadcast). /31 and /127 are exceptions for point-to-point links.

Need 4 subnets → borrow 2 bits → new prefix /26, each with 64 addresses (62 usable).

  • ARP – resolves IPv4 → MAC on a LAN ("Who has 192.168.1.1? Tell 192.168.1.5"). Broadcast request, unicast reply, cached in ARP table.
  • RARP – legacy reverse (MAC → IP for diskless stations); replaced by DHCP.
  • GARP (Gratuitous ARP) – host announces its own IP/MAC unprompted; detects duplicates, updates neighbors after failover (VRRP/HSRP).
# inspect the ARP cache
arp -a          # Windows / Linux
ip neigh show   # Linux modern equivalent
⚠️ ARP has no authentication — attackers can poison caches (ARP spoofing → MITM). Mitigate with Dynamic ARP Inspection.

ICMP (L3) carries error and diagnostic messages — not user data. Types include Echo (ping), Destination Unreachable, Time Exceeded (traceroute), Redirect.

ping 8.8.8.8        # ICMP Echo Request/Reply → RTT + loss
tracert example.com   # Windows; uses TTL expiry → Time Exceeded
traceroute example.com  # Linux; UDP or ICMP variants
⚠️ Many networks rate-limit or block ICMP — "Request timed out" may mean filtered, not down. Confirm with TCP (port 80/443).

TTL (Time To Live) is an 8-bit IP field decremented by each router; at zero the packet is dropped with an ICMP Time Exceeded back to the sender — preventing infinite loops.

Traceroute trick: send packets with TTL = 1, 2, 3… Each router along the path expires one and reveals itself. Three probes per hop give latency samples; * means no reply (filtered/slow).

MTU = largest frame a link accepts (Ethernet = 1500 B). If a packet exceeds it, IPv4 routers fragment it; the receiver reassembles. IPv6 forbids router fragmentation — the sender must use Path MTU Discovery.

  • Too much fragmentation → CPU cost, loss amplification (lose one fragment, retransmit all).
  • Fix: TCP MSS clamping, correct MTU on tunnels (VPN overhead shrinks effective MTU).
  • DF (Don't Fragment) bit + ICMP "Fragmentation Needed" drives PMTUD.

VLSM = use different mask lengths per subnet to fit each requirement. Rule: find smallest host-bits h with 2h − 2 ≥ needed hosts.

# Need 100, 50, 20 hosts from 192.168.10.0/24 — allocate largest first
100 hosts → h=7 (126 usable) → 192.168.10.0/25   (.0–.127)
 50 hosts → h=6 (62 usable)  → 192.168.10.128/26 (.128–.191)
 20 hosts → h=5 (30 usable)  → 192.168.10.192/27 (.192–.223)
# .224–.255 still free for growth

# Client opens connection to server
Client ── SYN (seq=x) ──────────────→ Server
Client ←── SYN-ACK (seq=y, ack=x+1) ── Server
Client ── ACK (ack=y+1) ──────────────→ Server
# Connection ESTABLISHED — data flows
  • Why 3? Each side must confirm the other's sequence number and readiness. Two messages can't confirm both directions.
  • Server allocates state after SYN → SYN floods can exhaust it (mitigate with SYN cookies).

Graceful close is a 4-way exchange (each direction closes independently since TCP is full-duplex):

A ── FIN ──→ B   (A: "I'm done sending")
A ←── ACK ── B
A ←── FIN ── B   (B: "I'm done too")
A ── ACK ──→ B
# A waits TIME_WAIT (2×MSL) to catch stray segments

An abrupt RST kills the connection immediately (crashed peer, rejected port, firewall).

Every byte gets a sequence number; the receiver returns an ack = next expected byte. Gaps trigger retransmission of exactly the missing bytes (selective ack / SACK).

# Sender transmits bytes 1–3000; bytes 1001–2000 lost
Receiver → ACK 1001   (got 1–1000, SACK 2001–3000)
Sender retransmits only 1001–2000
Receiver → ACK 3001   (all received, in order)
  • Flow control (receiver protection) – sliding window: receiver advertises rwnd; sender never exceeds it. Zero-window → sender pauses (persist timer).
  • Congestion control (network protection) – sender maintains cwnd: slow start (exponential growth), congestion avoidance (AIMD linear growth), fast retransmit/recovery on 3 duplicate ACKs.
  • Effective window = min(rwnd, cwnd).

Minimum 20 bytes: src/dst ports (16b each), sequence, ack, data offset, flags (SYN/ACK/FIN/RST/PSH/URG), window, checksum, urgent pointer + options (MSS, SACK, timestamps, window scaling).

💡 UDP header is only 8 bytes: src port, dst port, length, checksum. That's why it's fast — and why it guarantees nothing.

A socket is one endpoint of a connection: IP + port + protocol. A full connection is a socket pair (client socket ↔ server socket).

# server listening, client connected — same server socket, many connections
Server 10.0.0.5:443/TCP  ←→  Client 10.0.0.9:51234/TCP
Server 10.0.0.5:443/TCP  ←→  Client 10.0.0.9:51235/TCP
  • Loss-tolerant real-time – VoIP, video calls, gaming: a late retransmit is worse than a dropped frame.
  • Tiny queries – DNS fits in one datagram; TCP setup would triple the cost.
  • Broadcast/multicast – TCP can't do one-to-many.
  • Custom reliability – QUIC (HTTP/3) rebuilds congestion control + security on UDP for speed and flexibility.

In TCP, one lost segment stalls everything behind it (strict ordering) — and HTTP/2 multiplexed streams inherit the stall. QUIC runs independent streams over UDP: loss in stream A doesn't block stream B; plus 0-RTT setup and always-on TLS 1.3.

DNS, DHCP & NAT
Q41 – Q50
  1. App checks cache → OS cache → /etc/hosts.
  2. Query goes to recursive resolver (ISP / 8.8.8.8 / 1.1.1.1).
  3. Resolver walks the hierarchy: root → TLD (.com) → authoritative nameserver, caching each level (TTL).
  4. Final A/AAAA record returned to client and cached.
nslookup example.com      # quick check
dig example.com +trace       # full delegation walk
dig example.com +short       # just the answer
  • Recursive – client ↔ resolver: "get me the final answer." Resolver does all the work. (What your PC asks.)
  • Iterative – resolver ↔ name servers: "here's the best referral I have." Root says "ask the .com server", .com says "ask example's server". (What resolvers do upstream.)
⚠️ Open recursive resolvers get abused for DNS amplification DDoS — always restrict recursion to your clients.

DHCP delivers IP, mask, gateway, DNS, lease time. Renewals at 50% (T1) and 87.5% (T2) of lease. No server → APIPA 169.254.x.x.

  • Static – manually configured, never changes. Servers, printers, gateways.
  • Dynamic – leased from DHCP pool; may change. Laptops, phones.
  • Reservation – DHCP always hands the same IP to one MAC. Best of both: central control + stable address.

HTTP, HTTPS & Web
Q51 – Q60

HTTPS = HTTP inside TLS (port 443 vs 80). TLS adds encryption (confidentiality), authentication (server cert), and integrity (tamper detection).

  • HTTP is plaintext — anyone on path reads/modifies it.
  • HTTPS still leaks destination IP + SNI (mostly) unless ECH is used; body/headers/cookies are encrypted.

TLS 1.2 (simplified): ClientHello (ciphers) → ServerHello + cert + ServerHelloDone → client verifies cert, sends premaster (encrypted with server public key) → both derive session keys → Finished. TLS 1.3: collapses to ~1-RTT, forward-secret key exchange only, 0-RTT resumption option.

💡 Certificates bind domain → public key via a CA chain; the client trusts the CA list in its OS/browser.

Routing & Switching
Q61 – Q70

On each ingress frame the switch records src MAC → port in its CAM table (aging ~5 min). Dst lookup: known unicast → forward one port; unknown/broadcast/multicast → flood all ports in the VLAN. This "learn + flood" is why the first packet to an unknown host hits everyone.

⚠️ MAC flooding (attacker fills CAM) forces fail-open flooding → eavesdropping. Mitigate with port-security limits.

A VLAN is a logical L2 broadcast domain on shared switches — departments isolated without separate hardware.

  • Access port – one untagged VLAN to an end host.
  • Trunk port – carries many VLANs tagged with 802.1Q headers between switches/routers.
  • Inter-VLAN traffic must go through a router/L3 switch (router-on-a-stick or SVIs).

Redundant switch links create loops → broadcast storms + MAC flapping. STP (802.1D/RSTP 802.1w) elects a root bridge and blocks redundant ports, unblocking on failure. Modern variants: RSTP (fast), MSTP (per-VLAN-group instances).

  1. Verify dst MAC is its own, strip L2.
  2. Longest-prefix-match lookup in routing table (most specific route wins).
  3. Decrement TTL (drop at 0), rewrite src/dst MAC for next hop, forward.
  4. If no route → ICMP Destination Unreachable.
# example table: 10.1.2.0/24 via eth1 wins over 10.0.0.0/8 via eth0
10.0.0.0/8 via eth0
10.1.2.0/24 via eth1  ← longest match for 10.1.2.9
  • Static – hand-configured routes. Simple, zero overhead; breaks if topology changes. Fine for stubs.
  • Dynamic – protocols (OSPF, BGP) exchange reachability and reconverge automatically. Required at scale.
  • Hybrid reality: static defaults at the edge + dynamic in the core.

An AS is a network under one admin with one routing policy (ISPs, clouds — each has an ASN). eBGP runs between ASes (Internet routes, policy filtering); iBGP runs inside one AS (needs full mesh or route reflectors; doesn't modify next-hop by default).

  • Distance-vector (RIP, EIGRP-classic) – "routing by rumor": tell neighbors your distances; Bellman-Ford. Simple, count-to-infinity risk (fixed with split horizon, poison reverse).
  • Link-state (OSPF, IS-IS) – flood the topology so every router computes its own shortest path (Dijkstra). Faster, loop-free, more CPU/memory.
  • Collision domain – devices that can collide (share the wire). Each switch port = own collision domain; hubs = one big one.
  • Broadcast domain – devices receiving each other's broadcasts. Each VLAN/subnet = one; routers break them.
💡 Switches break collisions; routers (and VLANs) break broadcasts.

A VPN builds an encrypted tunnel over untrusted networks, making remote hosts appear local.

  • IPsec – L3 suite (AH/ESP, IKEv2); site-to-site and client VPNs. Transport mode (host-to-host) vs Tunnel mode (gateway-to-gateway).
  • SSL/TLS VPN – browser or client over 443; easiest through firewalls; portal or full-tunnel.
  • WireGuard – minimal, fast, modern crypto (Noise); static configs, roaming-friendly. Great for point-to-point/mesh.
  • Symmetric (AES/ChaCha20) – one shared key; very fast. Problem: key distribution.
  • Asymmetric (RSA/ECDH) – public/private pair; slow, used for key exchange + signatures.
  • Diffie-Hellman – lets two parties derive a shared secret over a public channel (TLS uses ECDHE for forward secrecy).
  • Real systems are hybrid: asymmetric to agree a key, symmetric for bulk data.

SSH (port 22) negotiates ciphers, authenticates the server via host key, then the user (password/keyboard/MFA or public-key), and opens encrypted channels (shell, port forwarding, SFTP, tunnels). Telnet (port 23) sends everything including passwords in plaintext — never use it on real networks.

ssh -i ~/.ssh/id_ed25519 user@host   # key login
ssh -L 8080:db:5432 user@bastion      # local forward to private DB
  • Volumetric – UDP amplification (DNS/NTP), floods. Mitigate: scrubbing centers, anycast, CDN absorption.
  • Protocol – SYN floods, ping of death. Mitigate: SYN cookies, rate limits, tuned stacks.
  • Application (L7) – slowloris, HTTP floods. Mitigate: WAF, CAPTCHAs, caching, per-IP throttling (429).
💡 Defense in depth: overprovision + edge filtering + autoscale + runbooks. No single box stops a big DDoS.
  • ARP spoofing – attacker answers ARP with its MAC for the gateway IP → victim traffic flows through attacker. Defend: DAI, static entries, 802.1X.
  • DNS spoofing/poisoning – forged responses redirect names to attacker IPs. Defend: DNSSEC, trusted resolvers, DoT/DoH.
  • MITM generally – position on path + downgrade/strip TLS. Defend: HSTS, cert pinning, VPN on untrusted nets.
  • WEP – broken (short IV, RC4 reuse). Crackable in minutes. Never use.
  • WPA (TKIP) – stopgap, also deprecated.
  • WPA2 (AES-CCMP) – solid, but 4-way handshake had KRACK; PSK vulnerable to offline dictionary if passphrase weak.
  • WPA3 (SAE/GCMP) – forward secrecy, stronger handshake, protects weak passwords, mandatory PMF. Prefer it; use Enterprise (802.1X) for corps.
  • DMZ – isolated subnet for public-facing servers between outside and inside firewalls; compromise there doesn't reach the LAN directly.
  • Zero Trust – "never trust, always verify": per-request identity, device posture, least privilege, micro-segmentation — no implicit trust from being "inside".

Server sends leaf + intermediates; client chains to a trusted root in its store, checking signatures, expiry, revocation (CRL/OCSP), hostname (SAN), and key usage. Any break → browser warning. Let's Encrypt made valid certs free and automated (ACME).

💡 Real speed ≪ headline rate: share airtime, mind channel width, RSSI, and interference.
  • CSMA/CD (wired legacy hubs) – listen, send, detect collisions, back off and retry. Gone on full-duplex switches.
  • CSMA/CA (Wi-Fi) – collisions can't be detected on radio, so avoid them: listen, random backoff, RTS/CTS handshake, ACK every frame.
  • Round-robin / weighted – even or capacity-proportioned spread. Simple; ignores current load.
  • Least connections / least response time – sends to emptiest/fastest backend. Best for uneven workloads.
  • IP hash / consistent hashing – same client → same backend (session affinity) with minimal reshuffle on scale.
  • Health checks (active/passive) remove dead backends — without them, balancing is theater.

MPLS forwards on short labels (between L2/L3) instead of longest-prefix IP lookups — fast, with traffic-engineering and VPN (L3VPN/VPLS) support. Still the backbone of enterprise WANs, though SD-WAN over commodity Internet is displacing pure MPLS for cost.

  • Dual-stack – run both; preferred long-term.
  • Tunneling (6to4, Teredo, 6in4) – IPv6 inside IPv4 to cross legacy cores.
  • Translation (NAT64/DNS64) – let IPv6-only clients reach IPv4 servers.

Troubleshooting & Tools
Q86 – Q90
  1. L1: link lights, cable, Wi-Fi associated? ip link, try another port/cable.
  2. L2/L3 local: got an IP? (ip addr — 169.254.x.x = DHCP failed). Correct mask + gateway? Ping gateway.
  3. DNS: nslookup example.com. If IP works but names fail → DNS issue; try 8.8.8.8.
  4. Path: ping 8.8.8.8, then traceroute to find the dying hop.
  5. App/port: curl -v, telnet host 443, check proxy/firewall.
💡 Always go bottom-up (L1 → L7). Most outages are L1/L2/DHCP/DNS, not exotic routing.
ping 8.8.8.8            # reachability + RTT/loss
tracert / traceroute example.com  # path + dying hop
ipconfig /all  •  ip addr / ip route  # own IP/gateway/DNS
nslookup / dig example.com      # DNS answers + timing
netstat -ano  •  ss -tulpn           # sockets: who listens/connects
arp -a  •  ip neigh              # L2 resolution sanity
curl -vI https://example.com      # HTTP status + TLS + headers
mtr example.com               # ping + traceroute combined
  • Capture with a display filter first: ip.addr == 10.0.0.5 && tcp.port == 443, or dns, dhcp, arp.
  • Follow TCP stream to rebuild a conversation; check SYN/SYN-ACK/ACK, retransmits (black/red), zero windows.
  • Verify each layer: ARP present? DHCP complete? DNS answers? TLS handshake aborts (cert?) or resets (firewall)?
  • Capture at both ends when possible — "sent but never arrived" localizes the drop.
tcpdump -i any port 53  # watch live DNS
tcpdump -i eth0 host 10.0.0.5 -w out.pcap

Routing works; the fault is higher up. Checklist:

  1. DNS? nslookup google.com fails → set/check DNS, flush cache.
  2. Proxy? stale PAC file or env http_proxy → bypass/disable and retest.
  3. Port 80/443 blocked? curl -v hangs vs instant RST → firewall/ISP filter.
  4. Browser-only? extensions, HSTS pin, captive portal login page.
  • mtr for 100+ packets: loss that starts at hop N and persists = problem at/after N; loss at one hop that recovers later = that router deprioritizing ICMP (ignore it).
  • Confirm with TCP-level evidence: Wireshark retransmits, app timeouts, iperf3 throughput collapse.
  • Common causes: duplex mismatch, bad cable/optic, saturated queue (bufferbloat), policer, faulty NIC offloads (test with offloads disabled).
